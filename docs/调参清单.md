# 调参清单（生产旋钮登记）

> 生产参数以 `app/config.py` 与各引擎 CLI 的实际默认值为准。本表用于发布审查；任何默认值、门控阈值或单位口径变化都必须同步更新本表。

| 参数 | 当前生产默认 | 含义 | 主要影响 | 变更要求 |
|---|---:|---|---|---|
| `expected_players` | 10 | 当前比赛场景预期球员数 | 影响产品层人数预期与结果检查 | 需按比赛制式确认 |
| `team_clusters` | 3 | 队伍/裁判颜色聚类数 | 影响队伍提示 | 改动需回归队伍聚类 |
| `confidence` | 0.25 | 检测置信度 | 漏检/误检平衡 | 需真实视频回归 |
| `imgsz` | 1280 | YOLO 输入尺寸 | 小目标召回与速度/显存 | 需 GPU 性能回归 |
| `vid_stride` | 1 | 处理帧步长 | 动态标定要求原始帧域 | **当前固定为 1** |
| `min_track_frames` | 10 | 极短轨迹过滤阈值 | 降低碎片 ID 与噪声 | 改动需追踪回归 |
| `min_presence_ratio` | 0.005 | 低出场轨迹过滤阈值 | 背景人员/短时误检过滤 | 改动需身份质量回归 |
| `min_turf_score` | 0.15 | 草地区域过滤阈值 | 场外人员过滤 | 需不同球场验证 |
| `min_track_turf_ratio` | 0.25 | 轨迹草地覆盖比例 | 场外/边线人员过滤 | 需不同机位验证 |
| `min_foot_y_ratio` | 0.55 | 脚点纵向位置门控 | 场内几何过滤 | 需不同画幅验证 |
| `event_percentile` | 92.0 | 事件分数分位阈值 | 事件数量/质量 | 需事件样本回归 |
| `event_min_gap` | 2.0 s | 事件最小时间间隔 | 避免同一动作重复切片 | 需高光回归 |
| `event_count` | 20 | 目标事件数量 | 高光/抽样规模 | 需报告展示确认 |
| `pre_sec/post_sec` | 3.0 / 2.0 s | 事件前后切片窗口 | 切片上下文长度 | 需产品体验确认 |
| `team_samples_per_id` | 12 | 每 ID 队伍特征样本数 | 队伍稳定性与计算量 | 需队伍识别回归 |
| `ocr_candidates_per_id` | 36 | 每 ID 号码 OCR 候选数 | 号码召回与计算量 | 需 OCR 回归 |
| `identity_audit_sample_stride` | 30 | 身份质量审计采样步长 | 审计速度与灵敏度 | 需 ID switch 回归 |
| `field_length_m/field_width_m` | 45 / 25 m | 场地米制尺寸 | 跑动距离、速度、2D 回放 | **必须按实际场地确认** |
| `calibration_tolerance_m` | 0.5 m | 独立尺度验证容差 | 标定是否允许进入米制链路 | 需标定负责人确认 |
| `dynamic_sample_step` | 5 | 动态标定采样步长 | 标定速度与平滑性 | 需覆盖率回归 |
| `dynamic_max_gap` | 30 | 动态标定最大插值间隔 | 可用帧覆盖率 | 需标定回归 |
| `dynamic_min_coverage` | 0.80 | 动态标定最低有效覆盖率 | 是否允许米制分析继续 | 不得为“跑通”随意降低 |
| `focus_clip_limit` | 12 | 重点高光上限 | 产品展示与导出体积 | 需产品确认 |
| `replay_max_frames` | 15000 | 2D 回放最大帧数 | 浏览器性能与回放完整度 | 需性能回归 |

## 与最初 POC 的关系

老板最初提供的 `pipeline(1)(4).py` 中，Stage 2 使用 `max_ids=35`、`min_track_frames=10`、`min_presence_ratio=0.01`，Stage 4 使用 `event_percentile=92`、`event_min_gap=2s`、`pre_sec/post_sec=3/2s` 等参数。当前产品化代码保留了“短轨迹过滤、出场过滤、事件分位阈值、事件间隔与前后窗”等核心口径，但已经增加场内过滤、动态标定、身份审计与产品层配置，因此**不能把 POC 参数逐项机械覆盖到当前生产配置**。

具体映射见 [`PIPELINE_BASELINE.md`](PIPELINE_BASELINE.md)。

## 变更登记规则

参数变更时至少记录：

1. 参数名与旧值/新值；
2. 改动原因；
3. 使用的回归视频/测试集（不要提交素材本体）；
4. 核心指标变化；
5. 确认人/确认日期；
6. 对部署性能、显存、结果口径是否有影响。
