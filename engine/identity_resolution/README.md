## 固化策略

1. 动态标定先过滤场外观测；不再使用固定单应性处理旋转机位。
2. 第一阶段保持严格，隔离 ID 不参与出生/消失、候选、训练或合并统计。
3. 第二阶段执行短间隔续接与长间隔找回；同帧、球衣、空间可达性、整组一致性和歧义门槛仍是硬约束。
4. 不按预期人数强制分配。短轨迹证据不足时保留为 isolated，原始观测仍可审计。
5. 训练与推理都要求 CUDA BF16；不允许静默退回 FP16/FP32。训练显式解冻全部参数。
6. 算法合并结果不会自动作为下一轮训练标签。
7. `filtered/identity_catalog.json` 是产品发布边界：只有包含至少两个源 ID 的确认组进入球员中心。

## 权重

- 检测：根目录 `models/yolov8x.pt`，容器启动时自动准备或从 UI 上传。
- ReID 初始化：`reid_model/weights/jx_vit_base_p16_224-80ecf9dd.pth`，由正式交付包携带。
- 每场模型：全参微调后写入该比赛临时工作区，随后归档到 MinIO。

实验目录、训练样本和历史输出没有复制进正式引擎。
