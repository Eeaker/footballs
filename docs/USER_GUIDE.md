# 用户指南

## 1. 创建比赛项目

在项目中心填写比赛名称、主客队和年龄组。每个项目独立保存输入、配置、日志、分析结果、人工复核和导出文件。

## 2. 上传视频和名单

上传比赛视频后，系统读取 FPS、分辨率、帧数和时长并做基础健康检查。球员名单支持 CSV/JSON；名单不是追踪启动的硬依赖，但会提升后续真实身份确认体验。

## 3. 配置分析参数

常用参数包括模型、置信度、输入尺寸、预期球员数、队伍簇数、事件阈值和号码候选数。动态标定要求原始帧域，因此 `vid_stride` 固定为 1。参数模板可导入/导出，但不会携带本机模型绝对路径。

## 4. 完成动态标定

固定拍摄点但会水平转动的素材不能用单一静态 Homography 覆盖整场。应在多个典型视角建立锚点，并用未参与拟合的已知长度线段做尺度验证。只有视频元数据、尺度误差和有效覆盖率通过后，米制分析才会启动。

## 5. 启动分析

界面展示四个阶段：

1. **追踪中**：人/球检测、BoT-SORT、场内过滤、技术 ID；
2. **号码识别**：队伍提示、多帧球衣号码证据；
3. **事件检测**：米制跑动、球权、球权转换、传球候选和事件；
4. **报告生成**：2D 回放、高光、球员卡、正式报告和归档。

失败或服务中断后，可从失败阶段重试；系统会先校验已完成阶段的核心产物是否仍完整。

## 6. 人工复核

- 号码存在冲突或证据不足时保持“候选/不可读”，不强填。
- 传球保留人工抽检入口，机器候选不等同于绝对真值。
- 技术 ID 可人工绑定真实姓名、号码和队伍。
- 八维能力分数只接受人工确认；8 项不完整时报告显示待评估。

## 7. 查看和导出结果

结果中心按业务视角组织：比赛总览、2D 回放、事件、高光、球员、质量/复核、报告、文件导出。项目可导出 ZIP，保留结构化 CSV/JSON、视频、报告和 artifact manifest。

## 8. 参考数据

`demo_data/reference_match` 是只读参考结果，用于 UI 和接口验收。它不参与正式项目计算，也不能替代目标 GPU 上的新素材端到端验证。
