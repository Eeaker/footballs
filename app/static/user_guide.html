FOOTBALL INSIGHT · V2.2

正式用户手册

系统面向完整比赛分析，不是一次性 Demo。正式项目从视频、参数和动态标定开始，经过 AI 分析和人工确认，最终生成 2D 沙盘、事件、高光、球员卡、报告与可归档数据。

01 输入比赛视频 / 名单
02 配置参数 / 多锚点动态标定
03 分析追踪 → 号码 → 事件 → 报告
04 交付结果中心 / 人工复核 / ZIP

1. 新建正式项目

在项目中心创建比赛。上传视频后系统自动读取 FPS、分辨率、帧数和时长。更换视频会让旧标定失效，防止不同素材的标定被误用。

2. 参数与名单

普通用户优先使用高质量 / 平衡 / 快速三档。名单支持 CSV / JSON，后续用于把技术 ID 人工确认成真实姓名与号码。

3. 多视角动态标定

固定拍摄点但相机会旋转时，建议在左 / 中 / 右等 2–4 个典型视角建立锚点。每个锚点使用 4–8 个对应点，并至少添加一条独立已知长度线段验证尺度。

标定硬门槛

只有每个锚点的独立尺度验证通过、且全片逐帧动态 Homography 有效覆盖达到要求，系统才允许启动依赖米制坐标的分析。

4. 正式 AI 分析

产品只显示四个阶段：追踪中 → 号码识别 → 事件检测 → 报告生成。失败或服务重启后会保留阶段状态，可从失败步骤重试。

5. 结果中心

按业务层级浏览：比赛总览、2D 动态沙盘、事件、TARGET 高光、球员卡、质量 / 人工复核、正式报告和数据导出。

6. 人工确认

系统不把技术 ID 自动当成真实球员。可结合名单、号码和视频把技术 ID 映射为姓名/号码；传球页可完成 20 条人工验收并实时计算一致率。

7. 导出与归档

完整 ZIP 包含配置、动态标定、分析结果、人工复核、报告与 SHA256 完整性清单。默认不把原始长视频塞进结果包。

8. 正式环境

系统状态页可检查依赖、GPU、ffmpeg、磁盘和 YOLO 权重，也可以直接上传 yolov8x.pt。所有启动前检查通过后才能跑新视频。

周五 10 分钟展示

视频上传 → 处理进度 → 2D 沙盘 → 1–2 个 TARGET 高光 → 球员卡 → A4 三步流程。演示页不展示命令行、ReID 精度和颜色切点。
